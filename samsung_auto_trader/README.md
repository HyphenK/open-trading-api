코드 기동을 위해서는 로컬 기준 .env 파일 내에 GH_ACCOUNT(계좌번호 8자리, -01 부분은 코드 내에 하드코딩으로 지정), GH_APPKEY, GH_APPSECRET 세 가지 값을 저장해두어야 합니다. API 키 발급은 한국투자증권 홈페이지 측에서 신청해야 하며, 이와 관련한 사항은 수업 중에 진행되었고, 관련 내용은 본 폴더 상위 폴더의 README 파일을 통해서도 확인할 수 있습니다.

본 코드는 지정된 단일 종목(티커)에 대하여 자동 매매 프로그램을 실행하며, 최초 코드 실행 시 정규장이 열려있는 시간(09시에서 15시 20분까지, 15시 20분부터 15시 30분까지는 정리매매 수행)대이면 지정한 개수만큼의 주식을 시장가로 구매한 뒤, 지정된 시간마다 시장가보다 일정 틱만큼 높은 가격에 지정된 주식 개수만큼의 매도, 일정 틱만큼 낮은 가격에 지정된 주식 개수만큼의 매수 주문을 넣음으로서 변동성에 의한 시세 차익을 추구합니다.

관련하여 티커 설정, 최초 구매 주식 개수, 매 번 주문을 넣는 주식 개수 등의 설정은 config.py 파일에서 작성합니다. 이에 대한 이해를 돕고자 005930(삼성전자)이 아닌 다른 가격대를 가져 이에 맞는 설정값을 부여한 티커(114800, KODEX 인버스 ETF)를 이용한 로그를 첨부하고자 하였으나, 6월부로 코스피 상승으로 인해 본 종목의 가격이 1000원 이하로 하락하였고, 모의투자에서는 한 주에 1000원 이하의 종목이 구매되지 않는 관계로, 부득이 원본 프로그램의 로그를 첨부합니다.

아래 내용 중 수량에 관한 부분은, 본 프로그램의 구동에 사용한 모의투자 계좌의 예수금 1천만원(최초 모의투자 신청 당시 내용에 의함, 현재 잔액 약 950만원)과, 코드 작성 당시 삼성전자 주가가 20만원 초반대였기에 이를 바탕으로 작성한 부분이며, 현재 삼성전자 주가는 30만원 초반대이므로 첨부한 6월 1일자 로그에서는 "즉 **최대 보유 상태에서도 약 20% 현금 버퍼**가 남도록 잡은 설정입니다." 라는 아래의 설명에 부합하도록 initial=12, min=3, max=25 에 해당하는 올바른 값으로 수정한 후 프로그램을 작동하였습니다. 본 코드 테스트 시 모의투자 계좌를 사용하였기에 초당 API 호출 횟수에 제한이 있어, trader.py와 orders.py 코드 동작 도중에 API 호출 횟수 초과에 의한 에러를 방지하고자 API 호출간 대기시간 1초를 부여한 부분이 있습니다. 이로 인해 코드가 한 사이클을 동작하는 데에 (특히 코드 실행 이후 시간이 지나 주문내역이 길어질수록) 약간의 시간이 소요되는데, 실제 계좌 사용시에는 이러한 제한이 완화되므로, config.py 파일에서 대기 시간을 더 짧게 지정할 수 있을 것입니다.

아래 내용 중 order_delete.py에 대하여, 이 코드는 개발과정에서 실행 중 발생하는 에러를 해결하고자 만들었던 임시 파일으로, 현재는 취소된 주문을 확인하는 로직은 메인 코드에 포함되었고(코드상에서 주문 조회 기능을 통해 사용할 준비는 되어있고 잘 작동하는 것은 확인하였으나, 이 기능을 활용한 추가 기능을 개발 과정에서 구현하지 않기로 결정함에 따라 현재 코드 로직상 무언가에 사용하지는 않습니다.) 이 파일 작성 당시에 발생하던 에러는 더 이상 발생하지 않아 사용할 필요가 없는 코드입니다.

# Samsung Auto Trader

한국투자증권 Open API 모의투자 환경에서 삼성전자(005930)만 대상으로 동작하는 REST 기반 자동매매 예제입니다.

## 이번 버전의 핵심 추가사항

- **재고 관리 한도**: `INITIAL_POSITION=20`, `MIN_POSITION=5`, `MAX_POSITION=40`
- **장중/재실행 초기화**: 장이 열려 있고 삼성전자 보유 수량이 `INITIAL_POSITION`보다 적으면 시장가로 부족분을 채운 뒤 루프 시작
- **장 마감 전 정리**: `15:20 KST`부터 미체결 주문 취소 후 매도 가능 수량을 시장가로 정리
- **장 종료**: `15:30 KST` 이후 자동 종료

## 특징

- REST API만 사용
- 모의투자 전용
- 토큰 same-day 캐시 재사용
- KST(Asia/Seoul) 기준 거래 시간 판정
- 주문가는 주문 직전 **호가단위 자동 보정**
- **최대/최소 보유량 제한**
- **상태 블록 로그**로 보유량과 미체결 주문 한눈에 표시

## 기본 설정값

`config.py` 기준:

- `INITIAL_POSITION = 20`
- `MIN_POSITION = 5`
- `MAX_POSITION = 40`
- `BUY_OFFSET_KRW = 1000`
- `SELL_OFFSET_KRW = 1000`
- `CLOSEOUT_START = 15:20`
- `TRADING_END = 15:30`

총 투자금 1,000만원에서 삼성전자 주가를 약 20만원으로 가정하면,

- 초기 20주 = 약 400만원
- 최대 40주 = 약 800만원
- 최대 보유 시 남는 현금 = 약 200만원

즉 **최대 보유 상태에서도 약 20% 현금 버퍼**가 남도록 잡은 설정입니다.

## 동작 흐름

### 1) 장 시작 전/직후

- 09:10 KST 전이면 대기
- 09:10 KST 이후 첫 진입 시 `INITIAL_POSITION` 점검
- 보유 수량이 20주보다 적으면 **시장가 매수**로 부족분 충당
- 이미 20주 이상이면 추가 초기화 없이 본 거래 루프 시작

### 2) 일반 거래 루프

1. 현재가 조회
2. 잔고 조회
3. 미체결 주문 조회
4. 상태 블록 출력
5. 미체결 주문이 있으면 신규 주문 스킵
6. 보유 수량이 `MAX_POSITION` 미만이고 현금이 충분하면 지정가 매수 시도
7. 매수 후 5초 대기 후 재조회
8. 보유 수량이 `MIN_POSITION` 초과이고 `sellable_qty`가 있으면 지정가 매도 시도
9. 매도 후 5초 대기 후 재조회

### 3) 마감 전 정리

15:20 KST 이후에는:

1. 미체결 주문 조회
2. **가능한 주문 취소 요청**
3. 2초 대기
4. 잔고 재조회
5. 매도 가능 수량이 있으면 **시장가 매도**
6. 15:30 KST까지는 추가 신규 주문 없이 대기

## 중요 메모

- 시장가 주문은 `order-cash` 엔드포인트에서 `ORD_DVSN="01"`로 분리해 두었습니다.
- 정정/취소 주문은 `order-rvsecncl` 엔드포인트와 취소 TR ID를 `config.py`에 분리해 두었습니다.
- 계좌/환경에 따라 일부 TR ID나 응답 필드가 다를 수 있으므로, **문제가 생기면 `config.py`의 취소 TR ID/엔드포인트부터 확인**하세요.
- 미체결 주문 취소에는 주문번호와 주문조직번호(`order_branch`)가 필요할 수 있어, `open_orders.py`에서 함께 파싱합니다.

## 비상 정리 스크립트 (`order_delete.py`)

`main.py`가 실행 도중 중단되면, 기존 미체결 매수/매도 주문이 서버에 남아서 다음 실행 때 **과매수/과매도**처럼 보일 수 있습니다. 이럴 때는 아래 스크립트로 삼성전자(005930) 잔여 주문만 정리하세요.

실행:

```bash
python order_delete.py
```

동작:

1. 당일 삼성전자 미체결 주문 조회
2. 남아 있는 매수/매도 주문을 하나씩 취소 요청
3. `POST_CANCEL_SETTLE_SECONDS`만큼 대기
4. 다시 미체결 주문을 조회해 남은 주문이 있는지 확인

권장 사용 시점:

- `main.py`가 예외로 종료된 직후
- 서버 재부팅 직후
- 전략 수정 후 재시작 전
- MAX/MIN 재고 상태가 로그와 실제 서버 주문 상태가 어긋나는 것처럼 보일 때
